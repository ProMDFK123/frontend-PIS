La convención para nombrar archivos en Next.js (y React) depende del **tipo de archivo** que estás creando:

## 1. PascalCase (Para Componentes de React) 🧩

Utiliza **PascalCase** (o UpperCamelCase, donde cada palabra comienza con mayúscula, como `MiComponente`) para nombrar archivos que contienen **componentes de React**. Esta es la convención estándar en el ecosistema React.

* **Ejemplos:**
    * `UserProfile.tsx`
    * `ProductCard.tsx`
    * `SidebarMenu.tsx`
* **Razón:** Ayuda a distinguir visualmente los componentes de React de las etiquetas HTML nativas (como `div` o `span`).

***

## 2. camelCase (Para Utilerías y Lógica) ⚙️

Utiliza **camelCase** (donde la primera palabra es minúscula y las siguientes comienzan con mayúscula, como `miFuncionDeAyuda`) para nombrar archivos que contienen lógica, utilerías, *hooks* o servicios.

* **Ejemplos:**
    * `formatters.ts` (en la carpeta `/utils`)
    * `userService.ts` (en la carpeta `/services`)
    * `useAuth.ts` (para un *hook* personalizado)
* **Razón:** Es la convención estándar en JavaScript y TypeScript para nombrar variables, funciones y archivos de lógica.

***

## 3. Minúsculas / snake\_case (Para Rutas) 📂

Utiliza **minúsculas** (a veces con guiones o *snake\_case*) para las carpetas y archivos que definen las rutas de tu aplicación, siguiendo la estructura del **App Router**.

* **Ejemplos:**
    * `app/productos/page.tsx`
    * `app/dashboard/layout.tsx`
    * `app/api/users/route.ts`
* **Razón:** Las URLs (y por lo tanto la estructura de carpetas) se definen convencionalmente en minúsculas. Next.js busca nombres de archivos específicos como `page.tsx` o `layout.tsx`.

**En resumen:** Lo más importante es usar **PascalCase** para los componentes de React y **camelCase** para la lógica auxiliar.
